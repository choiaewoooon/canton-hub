홈페이지 페이지 구조를 어떻게 나눌까요?

레퍼런스 분석 결과를 바탕으로 3가지 구조를 제안합니다

A

TheTie 스타일 — 단일 롱스크롤 대시보드

모든 정보를 한 페이지에 배치. KPI 카드 → 차트 → 리더보드 → 뉴스 순서로 스크롤

페이지: 1개 (메인 대시보드)
장점: 한눈에 전체 파악, 개발 단순
단점: 페이지가 무거워질 수 있음, 데이터 많아지면 산만
B

CantonScan 스타일 — 멀티 페이지

Overview(홈) + Statistics + Validators + News 등 기능별 페이지 분리

페이지: 5~7개
구성:
  📊 Overview (KPI + 핵심 차트)
  📈 Statistics (상세 시계열 차트)
  🏆 Leaderboard (밸리데이터/앱 랭킹)
  📰 News (트위터 + 뉴스 피드)
  📅 Calendar (거버넌스/이벤트 일정)
장점: 깔끔한 정보 분류, 각 페이지 가볍게 유지
단점: 개발량 많음, 페이지 간 전환 필요
C

하이브리드 — 메인 대시보드 + 심화 탭

핵심 지표는 메인에 모으고, 상세 분석은 탭/서브페이지로 분리

페이지: 3~4개
구성:
  🏠 Dashboard (KPI + 가격차트 + B/M + 최신뉴스 요약)
  📊 Analytics (상세 차트 + 리더보드, 탭으로 전환)
  📰 Feed (트위터 + 뉴스 + 캘린더 통합)
장점: 일반 유저는 대시보드만, 심화 유저는 Analytics로 — 타겟에 맞는 경험
단점: 정보 배치 기준 설계가 중요
